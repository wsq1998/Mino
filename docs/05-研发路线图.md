## 一、基线：v1.3 已经有什么

| 模块 | 能力 |
|------|------|
| 形象 | 八态表情机（六基础态 + `hot` CPU 过载 + `working` 番茄钟）、全局视线跟随、眨眼/呼吸/打瞌睡、点击穿透 |

| 清理中心 | 六类白名单扫描、大文件猎人、缓存排行、应用残留、智能建议引擎、清理历史、全屏勾选 |

## 二、三条硬约束（决定了什么能做、什么要绕）

这三条是 Mio 的立身之本，新功能方案都必须先过这一关：

### 约束 1 · 零第三方运行时依赖
`package.json` 的 `dependencies` 是空的，这条路走得很干净，**不要为了一个功能引进 npm 包**。
所有方案优先用系统命令 / 系统框架 / Node 内置模块。

| 常见需求 | 别用 | 用这个 |
|---|---|---|
| HTTP 请求 | axios | Node 20 内置 `fetch`（Electron 33 自带） |
| 图片处理 | sharp | `sips` / `screencapture` |
| 图表 | ECharts / Chart.js | 原生 Canvas 2D（已有先例：两块 sparkline） |
| 存密钥 | keytar | `security add-generic-password`（自带钥匙串 CLI） |
| 文件哈希 | hash-wasm | Node 内置 `crypto` |

### 约束 2 · 删除类操作必须人手确认 + 只进废纸篓
现行安全模型：`shell.trashItem` 永不 `rm`、路径白名单仅 `$HOME/`、红/黄/绿三级梯队、二次确认。
**「定时清理计划」和「重复文件查重」都直接撞在这条上** —— 设计方案时必须说明如何不破坏它。

### 约束 3 · macOS TCC 权限是稀缺资源
每新增一类权限，用户就要多面对一次系统弹窗、多一层不信任。**要集中引入、一次讲清。**

| 功能 | 需要权限 | 拒绝后的表现 |
|---|---|---|
| 截图 | **屏幕录制** | 拿到黑图/空白，要主动检测并提示 |
| 锁屏（真锁屏） | **辅助功能** | 脚本报错 |
| 剪贴板 / 电池 / 磁盘 IO / 天气 | 无需权限 | —— |

## 四、P1 · 桌面小工具

### 4.1 快捷操作

```js
// 锁屏（真锁屏，需「辅助功能」）
osascript -e 'tell application "System Events" to keystroke "q" using {command down, control down}'
// 降级：只熄屏，零权限，但语义不同（不锁）
pmset displaysleepnow

// 截图 → 直接进剪贴板（需「屏幕录制」）
screencapture -i -c      // 选区
screencapture -c         // 全屏
screencapture -W -c      // 窗口

// 清空废纸篓
~/.Trash 已在现有路径白名单内 → 复用 clean-execute，逐项 shell.trashItem
```

| 动作 | 权限 | 关键设计点 |
|---|---|---|
| 锁屏 | 辅助功能 | 首次调用会弹窗。**失败必须降级到 `pmset displaysleepnow` 并明确告知"只熄屏未锁定"** |
| 截图 | 屏幕录制 | 三种模式（选区/全屏/窗口）。**要检测权限被拒**（返回黑图）并引导去系统设置 |
| 清空废纸篓 | 无 | 复用现有确认通道；按钮上要**显示将释放多少 GB** |

**联动价值**：`screencapture -c` 的结果会进系统剪贴板 → **天然被 4.2 的剪贴板历史捕获**。
两个功能连起来就是「截图 → 在历史里找回」，这是单独做任何一个都得不到的体验。

### 4.2 剪贴板历史

- 主进程 `setInterval` 800 ms 轮询 `clipboard.readText()`，比 hash 去重
- **10 条 FIFO，只存内存、不落盘**（重启即清空）
- 点击 → `clipboard.writeText()` 写回，同时置顶
- 可「钉住」某条不被顶掉

**隐私设计（必须做，否则这个功能会变成负债）：**

| 措施 | 说明 |
|---|---|
| 不落盘 | 只在内存，退出即消失 |
| 暂停监听 | 一键关闭，处理敏感内容时用 |
| 疑似密码过滤 | 长度 8–64、无空格、同时含大小写+数字 → 不收录 |
| 单条 / 全部删除 | 不用打开设置就能清 |

> ⚠️ 密码过滤是启发式，**一定会有误伤**。默认开启还是关闭需要在 PRD 里定 —— 我倾向默认开启，
> 但界面上给它一个显眼的「刚才那条被过滤了」提示，避免用户以为功能坏了。

### 4.3 整点报时

渲染层已有 1 s 时钟 tick，加一个整点判断即可，**成本近乎为零**。

建议一次做全可配置项，否则上线后必然被要求补：

- 报时时段（如仅 09:00–22:00）
- 是否语音（`say` 命令，可选）
- 与「免打扰时段」共用一份配置

### 4.4 显示 / 隐藏桌面图标 —— ❌ 已决定不做

**决策（2026-09-11）：本项砍掉，不进入任何批次。** 理由留档，避免以后反复讨论：

1. **它改的是系统设置，不是删文件** —— 现行安全模型（路径白名单 + 只进废纸篓）**完全覆盖不到它**。
   要引入它就得新开一整类「系统设置写操作」权限，配套读原值 / 可还原机制，收益与代价不成比例。
2. **`killall Finder` 会关掉用户所有 Finder 窗口** —— 正开着几个文件夹整理文件时会一次性全没。
3. **它是持久性的** —— 写进 `defaults` 后不会自己恢复，重启后桌面仍是空的，容易让人以为文件丢了。

P1 剩下的锁屏 / 截图 / 清空废纸篓 / 剪贴板历史性价比都更高，不需要这一项来凑数。

## 五、P2 · 陪伴感深化

### 5.1 天气卡片

| 方案 | 接口 | 取舍 |
|---|---|---|
| **免 key（推荐 v1）** | `https://wttr.in/<城市>?format=j1` | 零配置、零成本；返回 JSON；国内速度一般 |
| IP 定位 | `https://ipapi.co/json` | 零权限拿到城市，精度到城市级够用 |
| 有 key（可选） | 和风天气（国内快）/ OpenWeatherMap | 精度高，但要求用户注册填 key |

> ⚠️ **不要用 CoreLocation**。Electron 没有原生定位支持，要走原生模块 —— 直接违反约束 1。
> IP 定位的精度对「今天要不要带伞」这个场景已经完全够用。

必须处理：断网 / 超时 / 返回异常时**面板不能卡住**，显示「天气暂时拿不到」并保留其余卡片。

### 5.2 喝水提醒 / 护眼提醒

纯定时器，复用现有通知 + 气泡通道，**零成本**。

- 喝水：默认 45 分钟一次，可配；可加「今日已喝 N 杯」轻量进度
- 护眼：按 **20-20-20 法则**（每 20 分钟、看 20 英尺外、持续 20 秒）

> ⚠️ **风险是通知轰炸**。Mio 现在已经有「久坐提醒（45 min）+ 番茄钟 + 智能建议 + 磁盘告警」，
> 再加两个提醒会让人想把通知全关掉。建议**合并成一个「健康提醒中心」**统一调度，
> 全局一个免打扰时段，而不是各自为政。

### 5.3 接 LLM 让 Mio 能聊天

这是产品层级最大的一次跃迁（从「工具」到「伙伴」），也是唯一一个**能改变 Mio 定位**的功能。
技术上不难，难在设计。四个必答题：

| 问题 | 方案 |
|---|---|
| **API key 存哪** | **不要明文写 JSON**。调 `security add-generic-password -s mio-llm -w <key>` 存进 macOS 钥匙串，读取用 `security find-generic-password -s mio-llm -w`。零依赖，且和系统密码管理一致 |
| **人格怎么来** | 独立 system prompt；同时和表情状态机联动 —— 请求发出时切 `thinking`，回答时按情绪切 `happy`/`curious` |
| **成本怎么控** | 只在用户**主动发问**时调用；设 `max_tokens`；界面显示本次估算 token |
| **能不能不花钱** | 备选接本地 **Ollama**（`http://localhost:11434`），零成本 + 隐私最好，代价是要用户自己装 |

**v1 建议只做单轮问答**（不做多轮 agent、不做工具调用）。理由：多轮的上下文管理会迅速吃掉
`mio-messages.json` 的 200 条上限，而且成本不可控。先把「能聊、聊得像 Mio」做出来，再谈记忆。

## 六、v1.3 候选（此前遗留）

### 6.1 电池健康 —— 性价比最高的一项

```bash
ioreg -r -c AppleSmartBattery | grep -E 'CycleCount|DesignCapacity|MaxCapacity'
```

健康度 = `MaxCapacity / DesignCapacity`。**零权限、毫秒级返回、数据有真实决策价值**
（该不该换电池、二手值多少钱）。建议优先做。

### 6.2 磁盘 IO

`iostat -d -w 1 -c 2` 普通用户可跑。**但 macOS 上 `iostat` 的维度很有限**，
做出来大概率是「一个数字，看不出所以然」。建议降级为**状态页的一个小指标**，
不要单独做卡片。

### 6.3 重复文件查重 —— ⚠️ 高风险项

**性能是最大敌人**。全盘哈希扫描会让 Mio 变成一个卡顿源。

建议三级漏斗，逐级淘汰：

```
1) 按文件大小分桶（> 1 MB）      —— 只读目录项，秒级
2) 同尺寸组算前 4 KB 指纹        —— 读少量数据
3) 仍相同的算全量 sha256         —— 只对极少数文件做
```

配套硬性要求：**限制在用户目录**、**后台任务 + 进度条 + 可随时中止**、
**只出报告、绝不自动删**（删除一律回到现有的勾选 + 二次确认通道）。

### 6.4 定时清理计划 —— ⚠️ 直接撞约束 2

上一轮已经讨论过设计边界，结论固化如下：

| 决策点 | 结论 |
|---|---|
| 清理范围 | **只放行绿色梯队**（缓存/日志）。黄色（大文件、`node_modules`）永远手动 |
| 交互 | **默认静默**：出气泡 + 写清理历史，不弹窗、不打断 |
| 调度 | **Mio 启动时补跑**（错过就顺延），不做常驻守护 —— 省掉休眠/唤醒的一堆坑 |
| 可回溯 | 面板显示「上次自动清理：时间 / 释放了多少 / 清了什么」 |
| 开关 | 一键关闭，且要有「暂停 7 天」这种温和档位 |

## 八、建议的执行顺序

### ✅ 批次 1 · 低风险快赢（**v1.4.0 已交付**）
`整点报时` · `健康提醒中心（久坐/喝水/护眼）` · `开机自启` · `电池健康` · `前台应用智能隐身` · `多屏位置记忆修复`
