## 1. 背景

v1.3 已经完成「形象 + 状态监视 + 系统清理」三条线。但作为一个**常驻**桌面的伙伴，还缺三块：

1. **开局就不对**：Mio 不自启，每次开机都要手动召唤 —— 常驻工具不自启，等于不存在。
2. **该出现时不该出现**：`setVisibleOnAllWorkspaces` 让球体浮在**所有**桌面之上，看视频和做演示时它就挡在那儿。
3. **只会看，不会提醒**：状态中心能显示一切，但不会主动说话。

另外有两个既有缺陷要在本批次顺手修掉：外接显示器拔掉后球体可能跑到屏幕外找不回来；电池只有百分比，没有健康度。

## 3. 需求明细

### 3.A 开机自启动

**用户故事**：我重启电脑后，Mio 应该自己回来，而不是要我记着去启动台点一下。

| 项 | 内容 |
|---|---|
| 交互 | 设置页「通用」组一个开关 |
| 技术 | `app.setLoginItemSettings({ openAtLogin })` / `app.getLoginItemSettings().openAtLogin` |
| IPC | `login-get` / `login-set` |
| 默认 | 读取系统真实状态，**不预设默认值**（避免和用户在系统设置里的手动改动打架） |
| ⚠️ 关键约束 | **仅在打包版可用**。`app.isPackaged === false` 时（`npm start`）开关置灰并提示「开发模式不支持，打包后可开启」—— 否则会把 Electron 开发壳加进登录项，污染用户系统 |
| 验收 | 打开 → 「系统设置 → 通用 → 登录项」出现 Mio；关闭 → 消失；重启后 Mio 自动出现 |

---

### 3.B 整点报时

**用户故事**：我在专心做事，想知道几点了，但不想切窗口、也不想看菜单栏。

| 项 | 内容 |
|---|---|
| 交互 | 每到一个整点，Mio 冒个气泡说时间（如「现在是下午 3 点」） |
| 默认 | **开启**；时段 **09:00–22:00**；系统通知 **关闭**（只出气泡） |
| 可配 | 开关 / 起止小时 / 是否同时发系统通知 |
| 触发 | 复用渲染层已有的 1 s `tickClock`，检测 `mm===0 && ss<=1` |
| **防重复** | 记录 `lastChimeKey = "YYYY-MM-DD-HH"`，同一小时只报一次 |
| **休眠处理** | 唤醒后**不补报**已错过的整点，只报当前小时（补报会连响一串，很烦） |
| 制式 | 跟随系统 `Intl.DateTimeFormat().resolvedOptions().hour12` |
| 免打扰 | 与健康提醒共用「免打扰时段」，落在时段内不报 |
| 验收 | 改系统时间到 `xx:59:58`，等 2 秒应触发一次；同一小时内不重复；时段外不触发 |

---

### 3.C 健康提醒中心

**问题**：Mio 现有「久坐提醒（45 min）」，本批次还要加喝水和护眼。**三个独立定时器会变成通知轰炸** —— 用户最终会把通知全关掉，等于全废。

**方案：把提醒收敛成一个统一调度的中心。**

| 项 | 内容 |
|---|---|
| 提醒项 | 久坐 45 min（沿用现有文案与周期）· 喝水 45 min（新）· 护眼 20 min（新，20-20-20 法则） |
| 统一调度 | 单一 **1 分钟 tick** 检查各项是否到点；**任意两次提醒间隔 ≥ 3 分钟**，同分钟内只发一条、其余顺延 |
| 免打扰时段 | 默认 **22:00–09:00**，与整点报时共用一份配置 |
| 开关层级 | 总开关 → 三项各自开关 |
| 默认值 | 总开关 **开**；久坐 **开**（保持现状，零回归）；喝水 / 护眼 **关**（新功能由用户主动开启） |
| 文案 | 久坐「坐太久啦，起来活动一下」/ 喝水「该喝水了，顺便伸个懒腰」/ 护眼「看看 20 英尺外，让眼睛歇 20 秒」 |
| 表情联动 | 提醒时切 `curious` 态 3 秒 |
| 验收 | 把喝水间隔临时调到 1 分钟，应触发；三项同时到点时只发一条、其余顺延；免打扰时段内静默 |

> **默认值取舍说明**：久坐保持默认开启是刻意的 —— 它现在就是这个行为，改掉会造成「功能突然没了」的回归感。新增的喝水/护眼默认关闭，把「要不要更多打扰」的决定权交给用户。

### 3.D 电池健康

**用户故事**：我想知道这块电池还剩多少寿命，值不值得换。

| 项 | 内容 |
|---|---|
| 数据源 | `/usr/sbin/system_profiler SPPowerDataType`（**实测 0.12 s**，且是「系统设置 → 电池」的同一口径） |
| 字段 | `Cycle Count` · `Condition` · `Maximum Capacity` |
| 刷新 | 启动 1 次 → 每 **30 分钟** → 切到状态页且缓存超 5 分钟时刷新。**不放进 30 s 采样循环** |
| 展示（行） | `电池健康  100% · 循环 32 次`，可钻入 |
| 展示（详情） | 健康度大数字 · 状态（正常 / 建议维修）· 循环次数 · 适配器功率 · 是否在充电 · 满充容量 / 设计容量 |
| 配色 | ≥80% 绿 · 60–79% 橙 · <60% 红；`Condition !== Normal` 直接橙/红 + 文案提示 |
| ⚠️ 降级 | 解析不到电池（Mac mini / Studio / 台式）→ **整行隐藏**，不显示空卡 |
| 验收 | 数值与「系统设置 → 电池 → 电池健康」完全一致 |

> **为什么不用 `ioreg`**：实测 Apple Silicon 上 `ioreg` 顶层 `MaxCapacity` 返回的是**百分比 100**，而 `AppleRawMaxCapacity=4296` / `DesignCapacity=4382` 算出来是 **98.0%**，与系统显示的 **100%** 对不上（Apple 做了平滑）。`system_profiler` 才是权威口径，且只要 0.12 s，没必要为省这点时间去对不上账。

### 3.E 前台应用智能隐身

**用户故事**：我看视频 / 做演示时，Mio 不要挡在画面中间。

**⚠️ 现实约束（必须先说清）**：真正的「检测全屏」需要读取窗口的 `AXFullScreen` 属性，那要**辅助功能权限**——与本批次「零新增权限」的目标冲突，直接否决。

**方案：改用「前台应用名单」+ 手动兜底。**

| 项 | 内容 |
|---|---|
| 探测 | 主进程每 **2 s**：`lsappinfo front` → `lsappinfo info -only bundleid <ASN>`（**实测 8.5 ms/次**，成本可忽略） |
| 命中行为 | **淡出而非隐藏**：`setOpacity(0.12)`。保留一丝存在感，鼠标移过去即可交互唤回 |
| 恢复 | 离开名单 → 还原为用户设定的透明度 |
| 默认名单 | 视频：IINA / VLC / QuickTime Player / 系统「视频」<br>演示：Keynote / PowerPoint / WPS 演示<br>会议：腾讯会议 / Zoom / 飞书 / 钉钉 |
| 手动兜底 | **新增全局快捷键 `⌥H`** 一键隐藏 / 显示。零成本、100% 可靠，覆盖「全屏游戏」等无法枚举的场景 |
| 命名 | UI 文案叫「**看视频 / 演示时自动隐身**」，**不叫「全屏检测」** —— 名实相符 |
| 降级 | `lsappinfo` 不可用 / 拿不到 bundleid → 静默跳过，只保留 ⌥H |
| 验收 | 播放 IINA → 球体淡化到 12%；切回 → 恢复；⌥H 手动切换正常；关掉总开关后不再自动隐身 |

### 3.F 多显示器位置记忆（缺陷修复）

**现状缺陷**：`mio-state.json` 只存了一组全局 `x/y`。外接显示器拔掉后，记录的位置可能落在所有屏幕之外 —— 球体「消失」，用户只能手改配置文件。

| 项 | 内容 |
|---|---|
| 存储升级 | `positions: { "<displayId>": { "x": …, "y": … } }` |
| 保存时机 | `moved` 事件 → 取窗口中心 → `screen.getDisplayNearestPoint()` → 按该屏 `id` 存 |
| 启动选址 | 取**光标所在屏** → 有记录用之；无记录则放该屏右下角 |
| **越界校验** | 记录的坐标不在任何 display 的 `bounds` 内 → **回退主屏右下角** |
| 兼容迁移 | 旧文件无 `positions` → 把现有 `x/y` 迁移为「主屏」记录，**不丢用户当前位置** |
| 验收 | 拖到副屏 → 退出 → 重开 → 回到副屏原位；拔掉副屏重开 → 自动回到主屏可见区域；升级后位置不变 |

## 5. 数据与持久化变更

`mio-state.json` 扩展（**全部向后兼容，缺字段即用默认值**）：

```json
{
  "x": 1200, "y": 600,
  "positions": { "1": { "x": 1200, "y": 600 } },
  "settings": {
    "chime":  { "enabled": true, "from": 9, "to": 22, "notify": false },
    "health": { "enabled": true, "sit": true, "water": false, "eye": false,
                "quietFrom": 22, "quietTo": 9 },
    "stealth": { "enabled": true }
  }
}
```

- `loginItem` **不落盘**：以 `app.getLoginItemSettings()` 为唯一真相，避免两边不一致
- 清理策略：仍是单文件覆盖写，体积无增长风险

## 6. 权限 / 风险 / 降级

| 项 | 评估 |
|---|---|
| **TCC 权限** | **零新增** ✅ 本批次全部能力都不需要弹权限窗 |
| `lsappinfo` 2 s 轮询 | 实测 8.5 ms/次 ≈ 0.4% 单核占用。优化：面板关闭且状态未变时降频到 5 s |
| `system_profiler` | 0.12 s，且 30 分钟才跑一次，可忽略 |
| 无电池机器 | 整行隐藏，不报错 |
| `lsappinfo` 不可用 | 静默跳过，保留 ⌥H 兜底 |
| 旧 state 文件 | 自动迁移，不丢位置 |
| **回归风险** | 久坐提醒周期与文案保持不变；现有通知通道不分叉 |
