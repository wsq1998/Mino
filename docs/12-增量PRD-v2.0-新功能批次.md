## 一、优先级总览表

### 1.1 评分维度说明

四项打分（1–5 分，5 最高）：

| 维度 | 含义 | 打分依据 |
|---|---|---|
| 价值 | 用户日常感知 / 痛点强度 | 用户 ★ 标记、使用频率、能否解决真实痛点 |
| 成本 | 实现成本（5 = 极低，1 = 高） | 复用已有数据/机制越多成本越低 |
| 权限 | 权限友好度（5 = 零新增，1 = 需新增） | 零新增权限优先 |
| 风险 | 安全/稳定性风险（5 = 低风险，1 = 高风险） | 是否触碰系统写操作 / 是否可能误伤 |

综合分 = 价值 × 0.35 + 成本 × 0.25 + 权限 × 0.2 + 风险 × 0.2

### 1.3 批次归属一句话理由

- **批次 1（P0 · 零权限快赢）**：8 项全部**零新增 TCC 权限**、全部能复用已有数据/机制（电池采样、剪贴板轮询、闹钟调度、天气 IP 定位、系统命令）。用户 ★★★ 的 AirPods 电量、文件暂存区进首批。
- **批次 2（P1 · 系统级操作 + 交互扩展）**：4 项涉及**系统级操作**（登录项增删、卸载入废纸篓、窗口 bounds）或**需要设计取舍**（文本片段与剪贴板关系）。权限零新增或复用已有（辅助功能/自动化）。
- **批次 3（P2 · 数据可视化 + 工程债）**：太阳图（重计算）、设置备份（低频）、三项工程债。**不阻塞前两批**，可随时并行。

### F1. 电量 / 满电充电提醒

| 项 | 内容 |
|---|---|
| 目标 | 电池数据已在采集（`batteryInfo()`：pct + charging），补上「低电量提醒充电、满电提醒拔电」的主动通知。macOS 无原生充电提醒，这是 Mio 的差异化价值。 |
| 用户故事 | 作为笔记本用户，我希望在电量 <20% 时收到提醒、充到 80%/100% 时提醒拔电，以便保护电池寿命、避免用到关机。 |
| 关键交互 | 主进程每 60s 检查一次电池状态（复用 `batteryInfo()`，不新增轮询频率）；状态变化触发通知（气泡 + 系统通知，走现有通知通道）；**去重**：同一阈值只提醒一次，直到状态反转（如从 <20% 重新充到 ≥20% 才复位）。 |
| UI 位置 | 设置 → 「提醒与通知」组新增子项：`低电量提醒（20%）` 开关 + `满电提醒` 开关；状态页电池卡片显示阈值状态。 |
| 默认值 | 低电量阈值 20%（可配 10/15/20/30）；满电提醒阈值 80%（可配 80/90/100）；两项默认开启；免打扰时段内静默（复用 `quietFrom/quietTo`）。 |
| 边界/降级 | 台式机无电池 → `batteryInfo()` 返回 null → 整组隐藏；提醒去重用 `lastNotifiedLevel` 状态（内存 + 落盘 `mio-state.json`，重启不重复轰炸）；充到 100% 但一直插电 → 只在「从 <阈值 变为 ≥阈值」的瞬间提醒一次。 |

### F2. 摄像头 / 麦克风占用警示

| 项 | 内容 |
|---|---|
| 目标 | 有 App 正在用摄像头/麦克风时，Mio 切「惊讶」表情 + 气泡提示「XX 正在用摄像头」。**零权限**（`lsof` 检测）。 |
| 用户需求 | 作为在意隐私的用户，我想在后台有 App 偷偷开摄像头时立刻知道，以便及时处理。 |
| 关键交互 | 主进程每 10s 轮询 `lsof +c 0 -n -i UDP`（摄像头：`/dev/video*` / `VDC` 设备；麦克风：`/dev/audio*`）→ 解析占用进程名 → 若与上次不同且非 Mio 自身 → 切 `surprised` 表情 + 气泡「XX 正在用摄像头」；点击气泡 → 打开状态页 Top10 进程（可结束）。 |
| UI 位置 | 状态页新增「隐私监控」小卡片（显示当前占用 App 列表）；表情联动。 |
| 默认值 | 默认开启；检测间隔 10s；只提示「有变化」的事件（不重复轰炸）。 |
| 边界/降级 | ⚠️ **macOS 已知局限**：某些 App（尤其浏览器标签页、部分视频软件）用完不释放设备，导致 `lsof` 持续显示占用。**必须**：① 提示文案写「可能仍在占用」而非「正在偷拍」；② 提供「忽略此 App」名单；③ 前台 App 占用是正常行为 → 静默展示在状态页，只对「非前台占用」做主动提示；④ 检测失败（异常）→ 静默跳过，卡片显示「不可用」，不影响其他功能。 |

### F3. AirPods / 蓝牙设备电量 ★★★

| 项 | 内容 |
|---|---|

| UI 位置 | 状态页新增「蓝牙设备」卡片（在电池卡下方）。 |

### F4. 自定义循环提醒 ★★

| 项 | 内容 |
|---|---|
| 目标 | 支持「每天 9 点吃药」「周三下午周会」这类循环提醒。**调度复用现有 alarm.js**（绝对时间戳驱动 + 持久化）。 |
| 用户需求 | 作为需要规律作息/吃药的用户，我希望设置「每天 9 点吃药」这类循环提醒，以便不用每天手动设倒计时。 |
| 关键交互 | 设置 → 「提醒与通知」组新增「循环提醒」区块：新增条目（名称 + 频率：每天/每周几/每月几号 + 时间 + 是否启用）；列表展示；编辑/删除（删除是删配置，不是删文件 → 普通确认即可）。主进程新增 `recurring.js`（纯函数层，可单测）：解析规则 → 计算下次触发时间戳 → 复用 alarm 的 `onFire` 通知通道。 |
| UI 位置 | 设置 → 提醒与通知组（新增「循环提醒」子区块）；触发时走现有通知通道。 |
| 默认值 | 无内置默认；新增条目默认启用；规则格式：`HH:mm` + `每天/周一~周日/每月 N 号`。 |
| 边界/降级 | 重启后补跑：**错过的不补**（与 alarm 语义一致，避免开机补发轰炸）；免打扰时段内静默；规则解析失败 → 表单校验提示，不落盘；最多 20 条（防滥用）；与倒计时互不干扰（独立命名空间）。 |

### F7. 应用卸载器 ★★★

| 项 | 内容 |
|---|---|
| 目标 | 拖 App 进来 → 连 App 带残留一起移入废纸篓。**删除走现有 6 道闸**（路径白名单 + 只进废纸篓 + 二次确认 + 只限用户目录 + 红/黄/绿梯队 + 清理历史）。 |
| 用户需求 | 作为想卸载 App 的用户，我希望拖一个 App 进来就能把它和残留一起清干净，以便不用手动翻 Library。 |
| 关键交互 | 清理页新增「应用卸载器」卡片：**拖拽 .app 图标进来**（或点选从 `/Applications` 列表选）→ 扫描该 App 的残留（复用 `leftovers-scan` 的孤儿目录逻辑，按 bundle id 匹配）→ 展示「App 本体 + N 个残留目录 + 总大小」→ 勾选 → 二次确认 → 全部 `shell.trashItem` 入废纸篓 → 写清理历史。 |
| UI 位置 | 清理页新增「应用卸载器」卡片（在残留卡下方）。 |
| 默认值 | 无默认；卸载前必须二次确认；**默认勾选全部残留，但 App 本体单独确认**（拆两步：先确认 App，再确认残留，降低误删风险）。 |
| 边界/安全 | ⚠️ **约束 2 合规**：全部走 `shell.trashItem`（可找回），绝不 `rm`；**白名单扩展**：`isBlacklistedPath` 目前只认 `$HOME/`，需扩展允许 `/Applications` 与 `~/Applications` 下的 `.app` 本体 + 其 `~/Library` 残留，其余路径仍走黑名单；卸载前检测 App 是否在运行（`pgrep`）→ 提示先退出；`/System` 与 Apple 签名系统组件 → 拒绝并提示；**卸载 ≠ 删除数据**：`~/Documents` 等用户数据绝不触碰。 |
