## 1. 产品目标

v1.3 把「监视」封顶、v1.4 把「提醒」做扎实、v1.5 把「设置」立好骨架 —— 但 Mio 始终是**只在看、只会在说**，用户还是得自己动手。v1.6 给 Mio 装上**第一条「执行」腿**：用户能一键让 Mio 锁屏、截图、清空废纸篓，能被 Mio 记住刚复制过的 10 条内容并随时取回，能把召唤自己的键改成顺手的，还能让番茄钟一开始就自动替用户挡掉所有打扰。这一批第一次触碰系统权限（屏幕录制 + 辅助功能），因此**权限体验本身就是交付内容**：宁可少一个功能，也要让用户看清「Mio 要这个权限干什么、不给会怎样、怎么反悔」，一次讲清、不吓人。

## 4. 需求池

> 优先级：P0 必须有 · P1 应该有 · P2 可以有。验收标准均写成**可断言的行为**。

### B2-1 剪贴板历史

| 编号 | 功能 | 优先级 | 验收标准 | 边界与例外 |
|---|---|---|---|---|
| CLIP-1 | 采集与展示（10 条 FIFO） | P0 | 依次复制 10 段不同文本 → 打开列表返回 **10** 条且最新在顶；第 11 段复制后仍为 10 条、**第 1 条被顶掉**、内容与系统剪贴板逐字符一致 | 空串/纯空白不收录；相邻两次内容完全相同 → 不新增、仅置顶该条；非文本（图片/文件）不采集 |
| CLIP-2 | 暂停监听 | P0 | 暂停后复制任意内容，列表条数与内容 10 分钟内**零变化**；恢复后新复制内容正常入列 | 暂停不清空已有历史；暂停状态**不跨重启**（重启即恢复监听，见 Q5） |
| CLIP-3 | 单条删除 / 全部删除 | P0 | 删单条 → 该条消失、其余相对顺序不变；全部删除 → 返回 **0** 条；删除后该内容无法再被取回 | 只删历史副本，**不改动系统剪贴板当前内容**；内存操作，不产生废纸篓记录 |
| CLIP-4 | 钉住某条 | P1 | 钉住第 3 条后复制 8 条新内容 → 第 3 条**仍在且位置不变**；取消钉住后该条可被正常顶掉 | 钉住条不参与 FIFO 顶替；钉住数量上限见 Q2 |
| CLIP-5 | 疑似密码过滤（**默认关闭**） | P1 | 默认设置下过滤开关为 **关**；开启后复制「长度 8–64、无空格、同时含大小写+数字」的串 → 不收录、条数不变；复制含空格普通句子 → 仍收录 | 启发式**必然误伤**（如 `MyPassw0rd` 被误滤）；只影响采集、不改系统剪贴板；被过滤时是否提示见 Q3 |
| CLIP-6 | 保留条数（E2） | P1 | 设为 5 → 复制 6 条后返回 5 条；从 20 改回 5 → **立即裁剪**为最新 5 条（钉住条保留） | 档位仅 5/10/20（默认 10），不给自由输入；裁剪不产生通知 |

### B2-2 快捷操作三件套

| 编号 | 功能 | 优先级 | 验收标准 | 边界与例外 |
|---|---|---|---|---|
| ACT-1 | 锁屏（真锁屏，需辅助功能） | P0 | 已授权 → 触发后系统进入锁屏界面；未授权/被拒 → **不报错、自动降级为熄屏**，并明确告知「已熄屏，但**没有锁定**」+ 提供「去开启辅助功能」入口 | 无破坏性，**不要求二次确认**；权限被拒后每次触发都走降级并复述提示（系统弹窗本身只弹一次） |
| ACT-2 | 截图 → 剪贴板（需屏幕录制） | P0 | 已授权 → 选区/全屏/窗口三模式截图成功，结果进入系统剪贴板可粘贴；未授权/被拒 → **必须检测到并提示**「缺屏幕录制权限，截图会是空白」+ 深链；按 Esc 取消 → 不产生截图、不报错、不写任何历史 | 不静默失败（黑图/空图必须被识别并告知）；全屏模式在多屏下截「光标所在屏」（见 Q4）；窗口模式点选目标窗口 |
| ACT-3 | 清空废纸篓 | P0 | 废纸篓非空时按钮显示「清空废纸篓（可释放 **X GB**）」，X 与实际体积一致（±5%）；点击 → 弹出含释放量的二次确认；取消 → 废纸篓**零变化**；确认 → 执行并显示结果 | 废纸篓为空 → 按钮置灰并提示「已是空的」；逐项处理，个别失败则报告「已清 N 项 / M 项失败」；范围限 `~/.Trash`（见 Q6 的约束冲突） |

### 5.2 关键控件与交互细节

- **剪贴板详情页**：每行 = 内容预览（单行省略号）+ 右侧「钉」与「✕」两个小按钮；行点击 = 取回该条到系统剪贴板并置顶（行内闪一下「已复制」）；顶栏一行「全部清除」（走通用二次确认弹层）。
- **暂停按钮**：复用现有 `.switch`；暂停中卡片标题旁显示「⏸ 已暂停」灰字，避免用户以为坏了。
- **快捷操作卡**：三按钮等宽；「清空废纸篓」按钮**动态带释放量**（如「清空废纸篓 · 2.3 GB」），无内容时置灰。
- **录制器**：方形按键显示当前组合；录制中变强调色并显示「按下新快捷键…」；旁边一个「恢复默认」小按钮回 ⌥Space。
- **通用二次确认**：复用现有 `#confirmOverlay`，不新建弹层。
- **所有失败态**：一律「球体气泡一句话 + 面板内一行可点提示（带『去系统设置』）」双通道；不出现英文报错、不静默失败。

## 6. 权限申请的时机与文案（本批次重点）

### 6.1 原则

1. **按需触发，不在安装/首启时弹** —— 用户第一次**真的去点**需要权限的功能时，才走权限流程。
2. **一次讲清全部用途** —— 首次进入任一批次 2 权限功能前，先展示 **Mio 自己的一张统一说明弹层**（面板内，非系统窗），把**两项权限一起列出**再触发对应系统弹窗，绝不「这次吓一次、下次又吓一次」。
3. **被拒不惩罚** —— 拒绝后功能只降级或停用，其余能力不受影响；每次相关操作都给「去系统设置」深链，不做无提示的静默失败。

### 6.2 时机

| 时机 | 触发 | 动作 |
|---|---|---|
| 首次点「截图」 | 屏幕录制 | 先弹**统一说明弹层** → 用户点「继续」→ 触发系统屏幕录制授权 |
| 首次点「锁屏」 | 辅助功能 | 同上：先弹统一说明弹层 → 点「继续」→ 触发辅助功能授权提示 |
| 再次点（权限已决定） | — | **不再弹**统一说明弹层；若已被拒，直接走 5.3 的失败态 + 深链 |

> 说明：系统授权窗对本 App 只会弹一次（TCC 机制），所以「一次讲清」靠的是**我们自己的说明弹层只弹一次**这件事 —— 它在用户首次接触任一权限功能时，就把两项权限的用途一次性交代完。

### 6.3 统一说明弹层文案

```
标题：Mio 想帮你做两件事，需要两项系统权限

· 截图 —— 需要「屏幕录制」权限
  只在你点「截图」时读一次屏幕，截完即用。
  不后台录制、不保存、不上传。

· 锁屏 —— 需要「辅助功能」权限
  只在你点「锁屏」时模拟一次锁屏快捷键。
  不读取、不记录你的键盘输入。

你的剪贴板、截图、系统数据全部只在本机处理，从不上传。
不授权也能正常用，只是「截图」和「真锁屏」不可用
（锁屏会降级为只熄屏）。

[ 稍后 ]                         [ 继续 ]
```

### 6.4 被拒后的文案与深链

| 权限 | 被拒提示 | 深链 |
|---|---|---|
| 屏幕录制 | 「没有屏幕录制权限，截图会是空白。点这里去系统设置开启 →」 | `x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture` |
| 辅助功能 | 「已熄屏但未锁定。要真锁屏，去开启辅助功能 →」 | `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` |

> 深链打开后需提示用户「改完回到 Mio 再试一次」（系统不会自动回来）；本版不做轮询自动刷新权限态，用户重新进入功能时再检测。

## 7. 隐私设计的可验证要求（剪贴板）

| 要求 | 可验证的断言 |
|---|---|
| **不落盘** | 任意时刻 `userData` 下所有文件（`mio-state.json` / `mio-history.json` / `mio-messages.json` / `mio-clean-history.json`）**均不含**刚复制过的文本；退出重开 → 剪贴板列表返回 **0** 条 |
| **只在本机** | 剪贴板内容不出现在任何 IPC 返回值之外的网络请求中；本版剪贴板功能**不发起任何网络请求** |
| **暂停有效** | 见 CLIP-2：暂停期间列表条数、内容零变化 |
| **单条可删** | 见 CLIP-3：删除后该内容无法再被取回，且不影响系统剪贴板当前值 |
| **可整体关闭** | SET-1 关闭后立即清空并停止采集；关闭无需二次确认（因无落盘、无残留） |
| **采集边界** | 只采集文本；空串/纯空白不采集；非文本不采集；系统标记为「敏感/隐藏类型」的剪贴板内容不采集（P2，见 Q3） |

> 一句话给用户：**Mio 记的剪贴板活不过这次开机。**

## 8. 待确认问题

| # | 待确认 | 我的倾向 |
|---|---|---|
| **Q1** | **「截图 → 剪贴板 → 历史找回」这条联动其实不成立**：路线图 §4.1 假设截图结果会被剪贴板历史捕获，但历史**只采集文本**，图片进不了列表。怎么办？ | 倾向**本版如实不做该联动**：截图结果进系统剪贴板供直接粘贴即可，历史仍只认文本；把「历史支持图片」列为后续独立需求。**不建议**为一条联动把内存与复杂度拉高 |
| **Q2** | 钉住的条数要不要设上限？ | 倾向**上限 3 条**并占满时禁用「钉」（提示先取消一条）。无上限时用户可能把 10 条全钉住，功能退化成普通列表 |
| **Q3** | 密码过滤被误伤时，要不要给「刚才那条被过滤了」的可见提示？ | 倾向**给一次轻提示**（气泡「刚才那条像密码，已跳过收录」），否则用户会以为功能坏了。同时把「跳过系统敏感类型剪贴板」作为 P2 增强一并做 |
| **Q4** | 多显示器下「全屏截图」截哪块屏？ | 倾向**光标所在屏**（与 v1.4 启动选址口径一致，用户预期一致） |
| **Q5** | 「暂停监听」在重启后是否保留？ | 倾向**不保留**（重启即恢复监听）。理由：与「不落盘」一致；暂停是场景性动作，长期悬置反而让用户以为功能失效 |
| **Q6** | **「清空废纸篓」与硬约束 2 存在语义冲突**：它本质是不可逆的永久删除，做不到「只进废纸篓」。 | 倾向：明确它是本产品**唯一不可逆**的操作，并用三重护栏兜住 —— ① 强制二次确认且按钮先亮释放量；② 仅限 `~/.Trash`、路径白名单限 `$HOME/`；③ 走 macOS 原生「清空废纸篓」机制（Finder `empty the trash`），**绝不 `rm`**。请确认这一例外是否可接受 |
| **Q7** | 专注期间**到点的健康提醒**是「跳过」还是「结束后补发」？ | 倾向**跳过、不补发**。补发会在专注结束时连响一串，正是 v1.4 拼命避免的通知轰炸 |
| **Q8** | C9「通知方式」的**默认值**取哪个？ | 倾向默认**「两者」**（保持现状：报时/健康的系统通知与气泡按原有行为），把「只气泡」留作主动选择；避免升级后默认变了让老用户感觉提醒消失 |
