## 1. 产品目标（一句话）

**让 Mio 成为用户 macOS 上「少装 3 个 App」的桌面效率工具箱**：在零第三方依赖与「删除只进废纸篓 + 人手确认」两条硬约束下，一次性补齐电量/蓝牙/隐私警示/网络/卸载/分屏/文本片段/文件暂存/磁盘可视化/设置备份等 13 项高频能力，全部落在现有菜单栏 + 快捷面板 + 设置中心里，不新增 TCC 权限类型。

> 判定标准：用户只装 Mio 一个工具，就能覆盖「看电量提醒、看 AirPods 电量、防摄像头被偷开、一键复制 IP、卸载 App、窗口分屏、暂存文件、快速输入文本片段、看磁盘太阳图、备份设置」10 个高频场景；全程 `dependencies` 仍为空、删除操作只进废纸篓、不新增任何系统权限弹窗。

### 2.2 明确不做（非目标）

- ❌ **不引入任何第三方依赖** —— 分屏/太阳图/卸载等一律用系统命令 + Node 内置 + 原生 Canvas，不引 npm 包（硬约束 1）
- ❌ **不新增 TCC 权限类型** —— 摄像头/麦克风警示用 `lsof`（零权限）；分屏若需辅助功能权限则走「集中引入、一次讲清」通道（见 Q2）
- ❌ **卸载不提供「彻底删除/清残留」默认选项** —— 删除一律 `shell.trashItem` 进废纸篓 + 二次确认（硬约束 2）
- ❌ **剪贴板图片历史默认不落盘** —— 沿用 v1.8 文本历史的内存策略，落盘需用户显式开启（见 Q1）
- ❌ **不做云同步 / 多设备** —— 设置备份导出为本地文件，导入仅本机

## 4. 需求池

> 优先级映射：★★★ → **P0**，★★ → **P1**，★ → **P2**，无星 → **P2**。验收标准均为**可断言行为**。

### F1 电量 / 满电充电提醒（★ → P2）

| 编号 | 功能 | 优先级 | 验收标准 | 边界与例外 |
|---|---|---|---|---|
| F1-1 | 实时电量轮询 | P2 | 主进程轮询 `pmset -g batt` 解析实时百分比（复用现有 `batteryInfo()`，但**不使用** `batteryHealth()` 的 30min 缓存路径），轮询间隔 60s | `pmset` 失败/无电池（台式机）→ 静默禁用该提醒，不报错 |
| F1-2 | 低电量提醒 | P2 | 电量 ≤ 20%（可配）→ 气泡 + 系统通知，仅提醒一次、避免轰炸 | 阈值可配（默认 20%）；同一阈值区间内不重复提醒，回升后再次跌破才再提醒 |
| F1-3 | 满电提醒 | P2 | 充电中电量 ≥ 80% → 提醒「可拔电」；= 100% → 提醒「已充满」 | 仅在**充电状态**下触发；80% 与 100% 各提醒一次；未充电不提醒 |
| F1-4 | 设置落点 | P2 | 设置 → 提醒组新增「电量提醒」开关 + 低电量阈值；默认**关闭**（避免打扰） | 与免打扰时段联动：免打扰时段内不弹 |
