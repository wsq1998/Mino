## 3. 发现并修复的缺陷

| # | 缺陷 | 根因 | 修复 |
|---|------|------|------|
| 1 | 浏览器中脚本整体失效、面板无法展开 | `id="mio"` 元素作为命名属性挂上 `window.mio`，桥接探测误判为 Electron 环境 | 桥接探测改为校验方法签名 `typeof getStats === 'function'` |
| 2 | Electron 中 app.js 完全无法解析 | `contextBridge` 已声明全局 `mio`，与顶层 `const mio` 冲突（SyntaxError） | 元素变量重命名为 `mioEl` |
| 3 | happy 表情弯月眼渲染成横线 | clip-path 方案在小尺寸下失真 | 改为透明底 + inset 顶部阴影弧线 |
| 4 | 内存占用恒显示 99~100% | macOS `os.freemem()` 不含缓存页口径误导 | 改用 `vm_stat` active+wired+compressor 计算 |
| 5 | Electron 二进制安装失败 ×3 | 官方源断连；沙箱代理阻断缓存写入/解压 | npmmirror 镜像 + 项目内缓存 + 系统 unzip 直解 |
| 6 | 应用启动即崩溃 | 外层沙箱阻断 Chromium sandbox 初始化 | 开发环境以 `--no-sandbox` 启动（生产打包不受影响） |
| 7 | 渲染帧销毁后 IPC 报错 | 光标轮询未捕获 webContents 异常 | send 加 try/catch |

## 4. 结论

MVP 全部 P0 功能通过端到端验证。已知限制：

- 全局快捷键 `⌥+Space` 与拖拽、右键菜单依赖真实鼠标，未自动化覆盖，需人工抽查
- 通知权限首次需系统授权
- 开发环境需 `--no-sandbox` 启动；打包分发后不存在此限制

## 1. 本轮新增断言（V18_*，共 8 项）

| 断言 | 验证点 |
|---|---|
| V18_SCHEMA | settings `_v:5` 长出 `autoClean` 组；默认关闭；general/appearance/.../weather 等老键一个不丢 |
| V18_AUTOCLEAN | 绿队假 target 被清空、黄队（夹带）纹丝不动；清理历史 +1 且标记 `auto:true`；`lastRun` 落盘；气泡通道被调用 |
| V18_AUTOCLEAN_PAUSE | `pausedUntil` 设未来 7 天 → 执行被 `skipped:'paused'`，清理历史不变 |
| V18_AUTOCLEAN_EXPIRED | `pausedUntil` 已过期（过去 1s）→ 不算暂停，正常执行并清空、写 `lastRun`（补充场景 B） |

## 2. 硬约束逐条对照（研发路线图 §6.3 / §6.4）

- **绿队硬门禁**：`runAutoClean` 仅对 `level==='green'` 放行；AUTOTEST 夹带黄队 target 验证其不被触碰（V18_AUTOCLEAN `yellowUntouched`）。
- **查重纯只读**：三级漏斗全程只算 sha256 指纹 + 分组返回，不写盘 / 不移动 / 不删除；测试数据统一走废纸篓（`shell.trashItem`）收尾，绝不 `rm`。
- **cancel 语义为真退出**：`V18_DEDUPE_CANCEL` 确认 canceled 标志 + 运行态停止 + 进度冻结。
- **并发互斥**：`runAutoClean` 与手动扫描 / 启动补跑共用同一执行闸门，同一时刻至多一个清理任务（`dedupeState.running` / autoclean 守卫保证）。

## 3. 本轮踩到的坑

- 补充场景需显式断言：单纯「3 同 1 异」的分组用例无法证明全量哈希生效——必须构造「前 4KB 相同、尾部不同」样本（V18_DEDUPE_LAYER23）才能排除「只靠前 4KB 指纹分桶」的隐患。
- 暂停语义要区分「未来时间跳过」与「过期即失效」两种语义，分别用 V18_AUTOCLEAN_PAUSE / V18_AUTOCLEAN_EXPIRED 覆盖。

## 4. 未自动化覆盖（需人工抽查）

| 场景 | 原因 |
|---|---|
| 真机「每天至多一次 + 启动 15s 补跑」跨天行为 | AUTOTEST 用假 target 验证单轮逻辑；跨天调度需真机等一天观察 |
| 真实大目录（数十 GB）下查重耗时与内存 | 需真实磁盘规模，AUTOTEST 用 1.2MB 样本验证正确性不验证性能 |
| 球体气泡里清理历史卡片的视觉呈现 | 自动化只验证事件通道被调用，视觉需人工看一眼 |

## 5. 结论

定时清理计划与重复文件查重两个功能落地，**零新增 TCC 权限、零新增第三方依赖**；
AUTOTEST 端到端覆盖绿队门禁、查重纯只读、取消语义、分组正确性（含前 4KB 同尾不同的边界）与暂停档过期语义。
批次 3（v1.6 剪贴板 / v1.7 天气 / v1.7.5 清理与查重）全部交付。
