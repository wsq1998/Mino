# Mio · 测试报告 v1.0

测试日期：2026-09-09　环境：macOS 14.8.7 (arm64) / Electron 33.4.11 / Chromium (agent-browser)

## 1. 测试方法

| 层 | 工具 | 覆盖 |
|----|------|------|
| 渲染层 | Chromium 浏览器自动化（点击/断言/截图） | 表情、面板、番茄钟 UI |
| 应用层 | Electron 自检模式 `MIO_AUTOTEST=1`（主进程驱动 capturePage + executeJavaScript） | IPC、桥接、真实系统数据、端到端交互 |

## 2. 自动化断言结果（Electron 端到端）

```
INIT:      panelOpen=boolean, POMO_WORK=number, dragging=boolean   ✅ 脚本完整初始化
AFTER_CLICK: {"panel":true,"cls":"...mio--happy"}                  ✅ 单击 → 面板展开 + 开心表情
POMODORO:  {"time":"24:58","state":"专注中…","working":true}       ✅ 番茄钟启动 + 工作状态绿环
STATS:     cpu=100% mem=76%                                        ✅ 真实系统数据（vm_stat 口径）
AUTOTEST_DONE
```

浏览器端同步验证：idle 形态、面板展开（21:42 时钟/日期正确）、番茄钟 24:57 倒计时中绿点亮起、思考表情 + 绿色轮廓。截图见 `docs/shots/`。

## 3. 发现并修复的缺陷

| # | 缺陷 | 根因 | 修复 |
|---|------|------|------|
| 1 | 浏览器中脚本整体失效、面板无法展开 | `id="mio"` 元素作为命名属性挂上 `window.mio`，桥接探测误判为 Electron 环境 | 桥接探测改为校验方法签名 `typeof getStats === 'function'` |
| 2 | Electron 中 app.js 完全无法解析 | `contextBridge` 已声明全局 `mio`，与顶层 `const mio` 冲突（SyntaxError） | 元素变量重命名为 `mioEl` |
| 3 | happy 表情弯月眼渲染成横线 | clip-path 方案在小尺寸下失真 | 改为透明底 + inset 顶部阴影弧线 |
| 4 | 内存占用恒显示 99~100% | macOS `os.freemem()` 不含缓存页口径误导 | 改用 `vm_stat` active+wired+compressor 计算 |
| 5 | Electron 二进制安装失败 ×3 | 官方源断连；沙箱代理阻断缓存写入/解压 | npmmirror 镜像 + 项目内缓存 + 系统 unzip 直解 |
| 6 | 应用启动即崩溃 | 外层沙箱阻断 Chromium sandbox 初始化 | 开发环境以 `--no-sandbox` 启动（生产打包不受影响） |
| 7 | 渲染帧销毁后 IPC 报错 | 光标轮询未捕获 webContents 异常 | send 加 try/catch |

## 4. 结论

MVP 全部 P0 功能通过端到端验证。已知限制：

- 全局快捷键 `⌥+Space` 与拖拽、右键菜单依赖真实鼠标，未自动化覆盖，需人工抽查
- 通知权限首次需系统授权
- 开发环境需 `--no-sandbox` 启动；打包分发后不存在此限制
