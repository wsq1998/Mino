## 一、为什么现在必须开这个功能

不是「想要一个设置页」，而是**现有结构已经装不下了**。

| 现状 | 问题 |
|------|------|
| 设置是「常用」tab 里的一个折叠卡片（`settingsCard`） | v1.4 已经有 8 个开关 + 2 个时段，一屏塞满 |
| 后续要加：剪贴板开关、快捷键自定义、天气城市、**LLM API Key / Base URL / 模型名** | 至少再涨 **25+ 项**，卡片彻底失控 |
| 设置项之间**没有分类**，全平铺 | 找不到、不敢改、改了不知道影响什么 |
| **敏感信息（API Key）无处安放** | 绝不能和其他设置一起明文写进 `mio-state.json` |

**结论：设置必须从「卡片」升级为「独立 tab」。**

## 二、形态决策

| 方案 | 评价 |
|------|------|
| **A. 独立第 4 个 tab**`常用 / 状态 / 清理 / 设置` | ✅ **推荐**。复用现有 tab 框架，零新增窗口逻辑；面板本来就是这个产品的唯一界面 |
| B. 点齿轮弹独立窗口 | ❌ 要新开 BrowserWindow + 新路由，且和「面板」两套 UI 要维护 |
| C. 沿用折叠卡片 | ❌ 见上，装不下 |

**采用 A。** 分组用 accordion（可折叠），默认只展开第一组；顶部可加一个**搜索框**（40+ 项时的刚需，成本很低）。

**API Key 的读写通道（零依赖）：**

```bash
# 写
security add-generic-password -a "$USER" -s mio-llm -w "<key>" -U
# 读（主进程内部用，绝不回传渲染层明文）
security find-generic-password -a "$USER" -s mio-llm -w
# 删
security delete-generic-password -a "$USER" -s mio-llm
```

> 🚨 **安全红线**：渲染层只能拿到 `sk-••••1a2b` 这种脱敏串；**真 key 永不进 IPC 返回值**。
> 测试连通性由**主进程**发起，渲染层只负责显示结果。

## 五、需要新增的底层能力

设置中心本身不重，但有 **7 个横切能力**必须先有，否则后面每个功能都要各自造轮子。

| # | 能力 | 方案 | 成本 |
|---|------|------|:---:|
| 1 | **设置 schema 版本化 + 迁移** | `settings._v = 2`，`migrate(s)` 逐版升级；复用现有 deep-merge | 低 |
| 2 | **钥匙串读写封装** | `keychainGet/Set/Del(service)` → `execFile('security', [...])` | 低 |
| 3 | **密钥脱敏** | 只回传 `前缀 + •••• + 末4位` | 极低 |
| 4 | **连通性测试** | 主进程 `fetch` + `AbortSignal.timeout(8000)` | 低 |
| 5 | **TCC 权限探测 + 深链跳转** | `systemPreferences` + `shell.openExternal` | 低 |
| 6 | **即时保存** | 开关一变就 `settings-set`，**不做「保存」按钮**（与现有 v1.4 交互一致） | 极低 |
| 7 | **危险操作二次确认** | 复用现有确认通道 | 极低 |

**零新增依赖、零新增权限**（I 组只做「检测 + 引导」，探测本身不需要权限）。

## 六、存量迁移

v1.4 的 `settingsCard`（8 开关 + 2 时段）**原样搬进新 tab 的 C 组**，然后删掉常用 tab 里的卡片。
迁移映射：

```
settingsCard.swLogin       → A1
settingsCard.swChime       → C1
settingsCard.chimeRange    → C2
settingsCard.swChimeNotify → C3
settingsCard.swHealth      → C4
settingsCard.swSit/Water/Eye → C5/C6/C7
settingsCard.quietRange    → C8
settingsCard.swStealth     → D3
```

**`settings` 结构体要做一次扩充**（现有只有 `chime/health/stealth` 三组）：

```js
{
  _v: 2,
  general: { login, autoOpen },
  appearance: { theme:'auto', size:'md', opacity:1, onTop:true, gaze:true, clickThrough:false, reduceMotion:false, displayId },
  chime:     { /* 保持不变，向后兼容 */ },
  health:    { /* 保持不变 */ },
  notify:    { style:'bubble' },
  stealth:   { enabled, opacity:0.12, apps:[...] },
  weather:   { enabled, city:null, interval:60, unit:'c' },
  ai:        { enabled:false, provider:'deepseek', baseUrl, model, monthlyCap, maxTokens, persona },
  data:      { /* 无设置项，仅操作 */ },
}
```

> `chime` / `health` / `stealth` **键名不动**，老用户升级后设置不丢 —— 这是 deep-merge 的天然好处。

## 九、S1~S3 的实现留档

| 决策 | 结论与理由 |
|---|---|
| 设置页形态 | **独立第 4 个 tab**。53 项设置，折叠卡片装不下；弹窗要新开 BrowserWindow，等于维护两套 UI |
| 折叠控件 | 原生 `<details>/<summary>`，**零 JS**；折叠标题带状态摘要（自启 / 主题·尺寸·透明度 / 报时·健康 / 名单数 / 版本） |
| 搜索 | 按行匹配、命中组自动展开、无命中给提示。40+ 项时是刚需 |
| schema 升级 | `_v:2` + **deepMerge**，不做逐版 migration 函数。v1.4 的 `chime`/`health`/`stealth` 键名保持不动 → 老配置零改动可用 |
| 写入协议 | `settings-set` 改为「只发改动的那一枝」，主进程深合并。渲染层不再回传整棵树 |
| 球体尺寸 | **`zoom` 系数**（0.8 / 1 / 1.13）而非逐个改 px。表情各状态里写死了大量尺寸，`zoom` 能整体等比缩放且仍参与布局 |
| 主题实现 | 840 行 CSS 收敛成 **17 个变量**（4 个 RGB 分量 + 4 档文本 + 3 档强调 + 2 档语义），替换 130 处硬编码 |
| **球体不参与主题化** | 深色玻璃是 Mio 的**角色身份**，不是界面配色。浅色下球体保持深色反而更醒目。实现上按注释标记切段整段跳过 |
| 跟随系统 | `matchMedia('(prefers-color-scheme: dark)')`，不需要 IPC |
| 隐身名单 | 名单可增删；「添加当前前台应用」用 `stealthTick` 记录的 `lastForeignFront`（**pid 比对排除自身**），解决「点开面板时前台已变成 Mio」的死结 |
| 不透明度 | 滑块 IPC 按 80ms 节流，标签拖动时即时跟手；窗口级外观统一到 `settings.appearance`，右键菜单写同一份设置 |
