# Mio · 增量 PRD v1.2 — P0 功能丰富化设计

> 版本：v1.2（增量，基于 v1.1）
> 平台：macOS（Electron 33，无第三方运行时依赖）
> 目标用户：Kaven —— M1 MacBook / macOS 15.8 / 磁盘 245GB 已用 90% / 开发者
> 用户反馈："状态中心和清理感觉有点简单，想要丰富一点"

---

## 1. 设计思路

v1.2 的主线是**"从仪表盘到参谋部"**：v1.1 的状态中心只是"看数字"，清理只是"扫垃圾"，v1.2 要让 Mio 成为用户管理这台 Mac 的参谋——状态中心从"瞬时读数"升级为"**全景体检 + 可操作管理**"（能看懂内存去哪了、能结束流氓进程、能回看 24h 峰值），清理从"固定六类"升级为"**以磁盘占用为线索的智能猎手**"（找到大文件、揪出应用残留、给出'这个 3GB 的 node_modules 30 天没动过'式判断）。所有丰富化围绕一条原则：**Mio 不只展示数据，而是基于数据给出结构化判断和一键操作**——契合 Kaven "先看清单 → 指定编号 → 分梯队确认" 的使用习惯。

## 2. 功能需求清单

### 2.1 状态中心丰富化

| # | 功能 | 描述 | 交互 | 数据来源 | 优先级 |
|---|------|------|------|----------|--------|
| S1 | 内存细分 | 将"内存占用"拆解为 App 内存 / Wired / 压缩内存 / 可用，附内存压力等级 | 速览行显示总占用；点击展开细分堆叠条 | `vm_stat`（pages × page size）+ `memory_pressure` | **P0** |
| S2 | 开机时长 | 本次开机时长 + 上次重启时间 | 状态页顶部一行小字 | `sysctl kern.boottime` | **P0** |
| S3 | 网络详情 | 本机 IP、WiFi SSID、当前连接数；点击刷新 | 网速行下方一行，展开时显示 | `ifconfig en0` / `networksetup -getairportnetwork en0` / `netstat -an \| wc -l` | **P0** |
| S4 | 进程管理 | Top5 → Top10 进程列表，支持按 CPU / 内存排序切换；长按或点 ⓧ **结束进程** | 列表项右侧 ⓧ → 二次确认弹层（"结束 XX？未保存工作将丢失"）→ `kill -TERM` | `ps -Ao pcpu,pmem,pid,comm -r` + `kill` | **P0** |
| S5 | 历史峰值 & 采样 | 内存 ring buffer 记录 24h 采样（30s/点），面板展示 CPU/内存 24h 迷你曲线 + 今日峰值标注；采样 JSON 持久化 | 趋势图下方小字"今日峰值 CPU 97% @14:32" | 内部采样器（复用现有采集）+ 本地 JSON | **P0** |
| S6 | 消息中心 | 面板内聚合 Mio 发出的所有通知记录（番茄钟、提醒、清理建议、磁盘告警），可清空 | 状态页底部"消息"折叠区，未读红点 | 内部事件总线 + JSON | **P0** |
| S7 | 磁盘 IO 速率 | 读写 KB/s 速览 | 磁盘卡片内一行 | `iostat -dK -w 1 -c 2`（**仅面板展开时**采样，收起即停） | P1 |
| S8 | 电池健康 | 循环次数、最大容量 | 电池卡片内一行 | `ioreg -rn AppleSmartBattery` 或 `system_profiler SPPowerDataType`（**仅展开时**，缓存 5 分钟） | P1 |

**明确不做（技术不可行，向用户说明）：**
- **CPU 温度 / 频率 / 风扇转速 / GPU 负载**：macOS 上唯一通用获取途径是 `powermetrics`，**必须 sudo**，违反"不引入 sudo 功能"红线。v1.2 的 hot 表情继续以 CPU≥90% 作为代理触发。

### 2.2 系统清理丰富化

| # | 功能 | 描述 | 交互 | 数据来源 | 优先级 |
|---|------|------|------|----------|--------|
| C1 | 大文件猎人 | 定位用户目录下 >500MB 文件，按大小排序 Top20，标注最后打开时间 | 清理页新卡片 → 扫描 → 编号清单（用户可回复编号指定，复用现有勾选流） | `mdfind -onlyin ~ 'kMDItemFSSize > 524288000'` + `mdls -name kMDItemLastUsedDate` | **P0** |
| C2 | 按 App 缓存排行 | ~/Library/Caches 按子目录聚合，Top10 应用缓存大小排行，可勾选清理 | 条形排行列表 + 勾选 + 二次确认 | `du -sk ~/Library/Caches/*/` | **P0** |
| C3 | 应用残留 | 对比已安装 App 列表，找出"App 已删除但支持文件还在"的目录（Application Support / Preferences / LaunchAgents 中的孤儿项） | 扫描 → 绿/黄分级清单 → 确认执行 | `/Applications`、`~/Applications` 的 bundle 列表 vs `~/Library/Application Support`、`Preferences`、`Containers`、`Saved Application State` 目录名比对 | **P0** |
| C4 | 智能建议引擎 | 规则化产出判断式建议，如"📦 node_modules × 3，共 3.2GB，最久 30 天未访问"、"Xcode DerivedData 8.1GB"、"下载文件夹 30 天前的安装包 5 个" | 清理页顶部"建议"卡，每条一个判断 + [定位] [清理] 按钮；每次扫描后刷新 | 规则集：`find ~/dev -name node_modules -prune` + `stat -f %a`（访问时间）、`du`；规则可扩展 | **P0** |
| C5 | 清理历史 & 释放统计 | 累计释放总量 + 每次清理记录（时间 / 项目 / 大小），持久化 | 清理页底部折叠区"已释放 12.4GB（近 30 天 4.2GB）"，可展开明细 | 本地 JSON（清理执行成功后追加） | **P0** |
| C6 | 重复文件 | 对 >50MB 文件按大小分组后 MD5 比对，列出重复组 | 清单 → 每组保留 1 个，其余移入废纸篓 | `mdfind` + `md5`（仅同 size 组内计算，控成本） | P1 |
| C7 | 清理计划 | 每周定时后台轻扫描，有可清理项时系统通知 + Mio 提示表情 | 设置开关 + 通知点击直达清理页 | 内部定时器（每周 1 次，复用扫描逻辑，静默运行） | P1 |
| C8 | 旧文件挖掘 | 下载 / 桌面中 N 天未打开的文件清单（默认 90 天可调） | 清单 + 勾选 | `mdfind -onlyin ~/Downloads 'kMDItemLastUsedDate < $time.today(-90)'` | P1 |

|---|------|------|----------|--------|

## 3. 交互与视觉规范

### 3.1 面板密度方案：240px 不够，引入「双档宽度」

- **紧凑档 240px（默认）**：保持现状布局，速览行（一行一个数字），信息密度不变。Mio 的第一印象仍是"轻盈的小球"，不变成监控大屏。
- **详情档 360px（展开）**：状态页 / 清理页内任何卡片点击 → 面板动画加宽至 360px（200ms ease-out），该卡片扩展为详情视图（细分数据 / 列表 / 排行）。同一时间只有一张卡片展开，收起回 240px。
- 理由：Kaven 要"深度和密度"但也要"即用即走"。双档比直接加宽到 360px 更克制，比弹独立窗口更符合单窗口架构。

### 3.2 卡片层级（三级信息架构）

| 层级 | 形态 | 内容 | 例子 |
|------|------|------|------|
| L1 速览行 | 一行：图标 + 数值 | 只放最关键的 1 个数字 | `内存 68%` |
| L2 卡片 | 进度条 + sparkline | 当前值 + 近 5 分钟走势 | CPU 卡片 |
| L3 详情 | 展开后的列表 / 表格 / 堆叠条 | 细分、排行、可操作项 | 内存细分、Top10 进程、缓存排行 |

### 3.3 趋势图（sparkline）规范

- 高度 20px，宽满卡片；**无坐标轴、无网格线**，纯折线 + 渐变填充（透明度 0.15）
- 点数固定 60 点（5 分钟 @5s 采样）；24h 历史曲线（S5）用 48 点聚合
- 颜色分级：<60% 冰蓝 `#85B7EB`，60–85% 黄 `#E0B84F`，>85% 红 `#E06A5A`
- 动画只用 `transform/opacity`，折线用 SVG path，path 更新不触发重排

### 3.4 视觉一致性

- 新增卡片沿用现有毛玻璃深色卡片（`#26282F` / 底色 `#17181C`），圆角、内阴影、描边不变
- 新增语义色仅两个：警告黄 `#E0B84F`、危险红 `#E06A5A`（现有绿 `#1D9E75` 保留为"健康/可清理"）
- 清理分级沿用绿/黄，新增**红色 = 只展示不清理**（见安全红线）
- 文字层级：主 `#EDEDF0` / 次 `#888A92` 不变；建议类文案前缀图标（📦🧹⚠️）帮助快速扫读

## 4. 安全红线（清理功能）

### 4.1 白名单（可清理范围，v1.2 全集）

仅限以下用户目录内的内容：
1. v1.1 已有六类（用户缓存 / 日志 / npm / pip / Xcode / 废纸篓）
2. `~/Library/Caches` 按 App 子目录（C2）
3. 应用残留：经 bundle 比对确认为孤儿的 `Application Support` / `Preferences` 目录（C3）
4. 大文件 / node_modules / 旧安装包：仅用户**勾选指定**的具体文件（C1/C4）

### 4.2 黑名单（永不展示为可清理，红色"只展示"分级）

- `/System`、`/usr`、`/Library`（系统级）任何内容
- `~/Library/Containers`、`~/Library/Group Containers`（沙盒数据，删除可能丢应用数据）——C3 残留比对**排除**此目录
- Keychain、Mail、Photos 图库、iCloud 占位文件（`mdls` 中 `kMDItemIsDownloaded = 0` 的文件跳过）
- 正在运行 App 的缓存（C2 排行中标注"运行中"，清理前需确认退出）
- 24 小时内创建/修改的文件

### 4.3 确认机制（分梯队，契合用户习惯）

- **绿队**：缓存 / 日志 / 残留 → 勾选 + 一次确认
- **黄队**：大文件、node_modules、旧安装包 → 勾选 + 二次确认（弹层列出将删除的完整路径）
- **红队**：只展示，不提供勾选
- 每次执行前弹层显示：**共 N 项，合计 X GB**，按钮文案写明"移入废纸篓"

### 4.4 可恢复性

- 所有删除**只走 `shell.trashItem`**，永不 `rm`；执行后显示"已移入废纸篓 [打开废纸篓]"
- 清理历史（C5）记录完整原始路径，作为事后追溯依据
- 进程结束（S4）：只发 `SIGTERM`（不 `kill -9`）；黑名单保护 `root` 进程、PID < 200 的系统进程及 `WindowServer / loginwindow / dock / finder`；二次确认文案明示"未保存的工作将丢失"

### 4.5 性能与电量红线

- 面板收起时：采样降频至 30s（v1.1 为 5s），24h 采样器维持 30s 不变
- `iostat`、`system_profiler`、`du`、扫描类命令**只在用户触发或面板展开时运行**
- 所有 `execSync` 命令带 3s 超时保护；扫描类走异步 `exec` 防主进程阻塞
- 待机 CPU < 1% 的 v1.0 红线不变

## 5. 范围裁剪

### v1.2 做（P0，共 13 项）

**状态中心**：S1 内存细分、S2 开机时长、S3 网络详情、S4 进程管理（含结束进程）、S5 历史峰值 24h 曲线、S6 消息中心
**清理**：C1 大文件猎人、C2 App 缓存排行、C3 应用残留、C4 智能建议引擎、C5 清理历史
**主动智能**：A1 主动建议卡片、A2 表情联动

### v1.3+ 留待（P1）

- S7 磁盘 IO 速率、S8 电池健康
- C6 重复文件、C7 清理计划（定期扫描提醒）、C8 旧文件挖掘

### 明确不做

- CPU 温度 / 频率 / 风扇 / GPU 负载（需 sudo 的 `powermetrics`，违反约束）
- 任何需要 sudo、原生 node 模块、重型依赖的功能
- 语音交互、多机器人（v1.0 范围外条款继续有效）
